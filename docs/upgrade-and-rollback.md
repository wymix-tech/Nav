旧画布 / AI 聊天 / Docker 监控用户请先阅读 [main 合并兼容修复](merge-repair-2026-10-17.md)。已被旧合并版本清空的坐标需要从部署前备份提取。

## 无限画布 V2 的当前升级步骤

本分支当前文档/写入协议为 **3**。以 [V2 操作说明](infinite-canvas-v2.md) 为准，先停写并备份数据库、uploads、配置和未同步草稿，再在隔离副本依次执行 `pnpm canvas-v2-preflight`、`pnpm canvas-v2-dry-run`、`pnpm canvas-v2-migrate`。数据库路径必须已经存在；普通 GET 不升级旧文档，全部文档迁移成功前停写。

写入要求 `schemaVersion: 3`、`snapshot.documentVersion: 3`、精确能力头、If-Match、稳定 operationId 和原认证。组、区域、名称、锁与层序保存在完整 state_json 的 canvasScene。默认相机仍为 canvasSettings.defaultCamera，本机相机和独立 namedViews 表不进入文档同步/导出。旧 pending 的操作 ID 和内容不能原地改写。

V1 的版本 2 和 `canvas-*` 命令仅是旧版本历史。本分支统一使用真实实现的 `canvas-v2-*` 命令，它能从更老网格/相机文档完整升级到 3，无须先部署 V1 再部署 V2。旧 V1 不能接管 V2 写入，也不能通过把版本号改回 2 来回滚；有 V2 编辑时先保留组织元数据，在副本核对后决定恢复方案。Dexie 4 不保证可由旧浏览器客户端降级打开。

## 部署前

1. 使用 Node.js 22 或更高版本与项目声明的 pnpm 9。执行 `pnpm install --frozen-lockfile`、`pnpm check`。
2. 设置实际 `NAV_DB_PATH`，执行 `pnpm db:preflight`。预检为只读，报告非法布局；不修改源数据库。先运行 `pnpm build` 生成维护程序。
3. 使用 `pnpm db:backup /absolute/path/backup.db` 创建一致性 SQLite 备份。WAL 模式下不得只复制正在使用的主 db 文件。目标目录需已存在，目标文件必须不存在。
4. 另行备份 uploads 目录与环境配置。保存旧镜像标识、代码提交与备份时间；备份包含私密配置，不应提交到 Git。
5. Docker 本版本以 UID 1000 运行。旧版本由 root 创建的持久卷需在停止旧容器并备份后，由管理员调整 `/data` 的所有权到 1000:1000，再启动新镜像。应用不会自动更改现有卷权限。

## 升级行为

- SQLite 只加表、加列，不删除旧表；迁移错误会停止启动，不吞掉异常。
- 服务端保存迁移前仪表盘 JSON；本地 IndexedDB 保留 v1 数据备份。缺失/损坏的历史数据不会被删除；预检和导出后再修复，不能以空盘覆盖。
- 基准列数与用户偏好分开。旧 lg 转为基准，保留合法高度；不直接启用旧 md/sm/xs 占位布局。窗口变化只影响展示，首次明确编辑才保存布局。
- 服务端写入改用带 `If-Match` 与 operationId 的原子快照接口。旧盲写客户端返回 426，需要刷新页面。不要让旧版本长期运行并写入同一数据库。
- 每个服务数据库拥有实例 ID。检测到实例替换时，旧离线草稿先隔离备份；有待同步操作时需要明确选择远端或重新提交，不能自动跨实例覆盖。
- SVG 上传与公开 SVG 返回关闭。旧 SVG 背景需要替换为栅格图片；旧合法栅格文件保留 URL，但返回前检查真实内容与路径。新上传转为 WebP，动画只保留第一帧。
- 旧插件保留配置与位置，显示升级提示；需要按 manifest v2 的隔离协议重新构建。安装与卸载需要网络，失败保留原状态；已安装插件记录有本地缓存。
- 默认不向访客公开系统监控。需要公开时显式设置 `NAV_PUBLIC_MONITOR=true`，返回内容会脱敏；磁盘路径需由 `NAV_MONITOR_DISKS` 允许列表指定。

## 离线与冲突

服务器模式不会因 health 超时改成无认证本地模式。仪表盘编辑先写 IndexedDB，再有序同步；保存状态区分本机已保存与远端已同步。网络或权限失败时保留草稿，可以导出 JSON 备份。

多设备发生版本冲突时不自动覆盖。采用远端或重新应用本地草稿之前，系统保存双方快照；再次发生冲突仍需处理。幂等记录保存最多 30 天并有容量上限；过期重试会受到版本条件保护，必要时进入冲突处理。

应用壳在生产构建成功加载并缓存后可离线打开；API 登录、插件安装、天气等外部服务不因此变成离线服务。新增版本不会强制中断编辑；结束编辑并处理待同步操作后再确认更新。

## 回滚

1. 暂停写入，让用户导出未同步草稿；停止新容器，避免恢复过程中继续重放队列。
2. 优先回滚到包含安全补丁、支持新 schema 的兼容镜像。不要直接退回原始 main。
3. 若只能恢复数据库备份，明确备份后的变更会丢失；保留升级后的数据库副本以便恢复，不在原文件上反复覆盖。
4. 恢复数据库、上传资源及匹配的配置。使用预检与只读页面检查后，再允许编辑和同步。
5. 清理或重新授权指向旧服务实例的离线草稿，避免把恢复前的数据自动写回。实例 ID、版本条件和隔离备份用于发现此类情况。

## 验证命令

```bash
pnpm check
pnpm exec playwright install chromium
pnpm test:browser
NAV_TEST_DIST=true pnpm test:browser
# 额外浏览器（需预先安装）：
NAV_TEST_BROWSERS=chromium,firefox,webkit pnpm test:browser
```

浏览器测试启动隔离测试数据库和本地服务，不应指向生产环境。真实 macOS Safari、系统显示缩放以及 Docker 卷升级需在对应环境补充验收；WebKit 自动测试不等同于 macOS Safari 实机验证。
