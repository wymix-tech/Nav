# V3 实现复核记录

范围：资源所有权、私有状态、可见性/分级展示、完整几何索引与 V2 兼容。V3 方案与当前操作分别见同目录 plan 和操作文档；此处记录实际发现并修复的边界，不把类型检查代替浏览器验收。

| 问题                                                            | 修复与证据                                                                                                                 |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 原 ChatWidget 卸载即 abort，草稿与请求属于 View                 | ChatRuntime 独占流；Registry attach/detach 无副作用，离屏/隐藏流、删除迟到片段、刷新中断与私有记录测试                     |
| 旧聊天记录缺少空间身份；绑定标记失败可留下半份导入              | 不自动导入；先预留唯一绑定再写新记录；故障与跨空间回归实际先失败，修复后重跑                                               |
| Docker 恢复时把暂停前缓存当作新速率基线                         | 共享采样显式区分 cached/fresh；缓存只展示，首个 fresh 重建基线；新增反向回归先失败                                         |
| 常规登录复核的 checking 状态可能误终止既有流                    | 保留现有会话的请求；真正 token 撤销/更换才 revoke。发送仍检查已验证权限。浏览器持续流中触发在线复核，验证零额外 abort/发送 |
| 删除 tombstone 的 20 项配额可能挤掉切换空间的脏草稿             | 区分删除恢复记录与非活动脏草稿；后者纳入软预算并保留。25 个草稿跨空间往返回归                                              |
| 每实例时钟/Docker 轮询放大资源；暂停返回可能集中发请求          | 单共享时钟、共享数据源去重、授权 epoch、采样并发上限与公平轮转；无需求解除订阅                                             |
| 插件目录对象刷新误重启 runner；仅固定 commit 又可能忽略权限收回 | 统一不可变入口＋网络权限/CSP 身份，展示名刷新保留 owner，权限变化替换；保留来源/secret/CSP 校验                            |
| 表单修改 Monitor 磁盘数组可提前污染文档                         | 复制草稿，源订阅只使用已接受配置；Weather 用接受时单位映射原始缓存                                                         |
| 索引可能因名称、配置或 ack 重建，或失效时阻塞编辑               | 几何/成员投影 epoch；精确线性参考；损坏/过期索引回退完整几何；seed 73019 随机对照                                          |
| 可见性变化可能造成输入法/指针孤儿 pin、旧定位抢焦点             | 引用计数保护及 lost capture/blur 清理，导航 serial/owner generation/激活序号校验；草稿/表单/20 轮循环浏览器回归            |
| 低倍率文本跟随世界坐标缩得不可读；巨大区域创建巨大绘制面        | 摘要文字按相机逆比例保持可读，outline 只留轮廓；区域绘制裁到视口，边框命中仍对应真实边缘                                   |

## 验证中的失败记录

- 第一轮资源计数使用 output，和保存状态的 role=status 冲突；改为普通 span，保留原状态断言。
- 首次资源需求参数没有传入内置 View，Monitor/Docker 因可选布尔属性默认 false 不采样；补齐显式传递并定向验证。
- Firefox 在容器中创建页面前崩溃；通过测试环境的内容沙箱配置和依赖准备运行，不修改产品安全协议。
- 首次 WebKit 新草稿用例在立即刷新后仍指向未保存的相机位置；恢复目标后再验证私有草稿，原相机/离线回归保留。
- Firefox 两个用例在初始异步详情尚未 ready 时替换数据并刷新，捕获旧页面被取消的动态导入错误；增加明确就绪条件，没有删 pageerror 或宿主身份断言。
- 自动审批审查中止过一轮浏览器验证：书签图标请求可能带出域名。测试统一加 context 路由，未打桩的外部请求一律阻断；仅隔离本地应用可真实联网。服务/插件使用固定合成桩，不使用生产数据或用户凭据。
- 构建过程中曾出现与并行检查重建 shared dist 交错的导出缺失；按顺序执行完整检查，保留最终构建与 CI 结果，不将中间失败记为通过。
- 恢复验证环境后的 WebKit 全套曾在聊天删除/撤销用例失败：文档已恢复，详情仍待挂载，10 秒内没有输入框。保留首次现场，未据此声称草稿丢失。带诊断和移除诊断后的单用例均完成连续 20 次删除/撤销；正式回归增强为 20 次并明确检查零聊天请求。根因尚未确定，不把后续重跑通过写成产品修复，也未放宽超时或移除原断言。跟踪项为 `V3-WK-UNDO-01`。
- 一次诊断重复命令宣布 15 个用例，但持久日志仅有 4 个完成行，没有完整结束摘要；不记为 15 次通过。临时诊断代码已移除。
- 临时浏览器环境与旧测试日志在会话恢复时已丢失；重新准备依赖并复测。新的完整检查、浏览器和生产/性能日志保留于当前验证交付材料。
- 生产全套中离线壳曾为 31 通过、1 失败：离线刷新正确保留草稿/相机，重连后立即再刷新，原页面可能已经持有 20 秒同步租约，新页面不能在原 10 秒断言内夺取租约。生产原逻辑由 30 秒心跳恢复。测试安装虚拟时钟，保留真实离线刷新和远端写入断言，在线刷新后推进 31 秒跨过该恢复窗口；定向复测通过。没有改生产同步逻辑、租约或断言超时。最终场景覆盖来自原 31 项和新离线壳定向运行，未伪称一次最终 32 项整套运行。
- 自动审批审查拒绝向 GitHub 推送新增源码与提交历史，原因是缺少对该目标披露的明确授权。没有改用其他写入接口；当前提交仅在本地，未创建 V3 PR、运行 V3 远端 CI、合并或部署。
