# 无限画布 V2：操作、协议与验收

实施分支：`feat/infinite-canvas-v2`。依赖 V1 `d79ac926857418b901c885a55377438beaeae398`，审查入口为 [PR #3](https://github.com/wymix-tech/Nav/pull/3)，暂以 V1 分支为 base。main 尚未包含 V1；本分支没有合并、部署或修改生产数据。设计依据见 [完整方案](infinite-canvas-v2-plan.md)，逐项证据见 [验证记录](infinite-canvas-v2-validation.json)。

## 已实现的交互

- 交互工具保留组件输入和背景平移；手形工具接管整个视口。编辑时可显式切换选择或区域工具。选择模式下双击组件或点击“进入组件”恢复内容交互。
- 选择单位是自由组件、单层组或区域。Shift 点击切换；框选按正面积相交命中内容，不自动选背景区域；Shift 框选始终相对开始集合计算。触屏有“增减选择”按钮，第二触点取消编辑草稿后交给双指导航。
- 移动阈值为 5 CSS px，预览只在内存。整批使用同一 delta，吸附联合包围盒，边界约束不改变相对位置。目标几何、成员或锁改变时取消整批；无关配置和组件变化不撤回导航。
- 选择工具下、宿主获得焦点时，Ctrl/Meta+A 选择全部内容；Ctrl/Meta+G 分组，Ctrl/Meta+Shift+G 解组；Delete/Backspace 删除所选。输入框、内容区域、对话框、iframe 的输入不被接管。Escape 优先取消活动手势并恢复原选择，否则清除选择。
- 分组至少两个自由组件，不改变坐标、ID 或宿主父级；解组保留组件。“删除组及组件”与解组是不同动作。图层面板支持加入、移出成员，剩余不足两个时自动解组；内部成员和外部图层分别排序。
- 区域是背景注释，无成员关系。区域工具拖出至少 40×40 世界单位的矩形，或以“框住所选”增加 24 世界单位边距。区域可命名、改色、移动、调整大小、锁定和删除，不带动组件。
- 图层支持前移、后移、置顶、置底，保持选中项相对顺序；组作为连续层序块。区域和内容是独立平面，混合平面排序被拒绝。渲染仍遍历原 widgets 数组，以 CSS rank 表示层序。
- 六向对齐至少两个选择单位；等距分布至少三个单位，按真实边缘间隙计算，首尾保持不动。负间距、越界、锁定导致整批拒绝。一次命令增加一次历史和一次逻辑保存，无变化不写。
- 智能吸附使用边缘、中心和有上限的等距候选，进入/保持阈值为 6/10 CSS px，参考范围扩展 64 CSS px，配对最多取 24 个近邻。无智能候选时回退 20 世界单位网格；Alt 或可见吸附开关关闭吸附。尺寸调整只吸附右/下活动边缘，并受最小/最大尺寸保护。

## 布局锁和其他展示模式

组件有效锁来自自身或所属组；组含锁定成员时整组几何和结构受保护。布局锁不替代认证，也不禁止原本允许的内容输入、配置保存、共享名称和显式层序管理。图层面板可展开并单独解锁成员。

几何、删除、组成员修改、网格显式布局编辑、整理、设为基准、清空和恢复都经过统一转换校验。服务端按**当前**文档的锁检查，不能在同一请求中解锁并移动；成功操作重试先按 operationId 去重。网格响应式派生显示仍不写文档。

网格和空间/列表切换保留 scene。列表按 y/x/id 派生 CSS order，不使用层序或组关系重排宿主 DOM。列表/网格可从图层面板管理名称、锁、组和删除，空间几何操作保持在空间视图。访客可使用搜索、定位和自己的本机视角。

## 搜索和本机视角

搜索只索引显示名称、ID、组件类型、内置/已安装类型名称，以及内置书签组件已验证的分组名、书签标题和 URL。聊天消息、输入草稿、令牌、插件任意配置、iframe DOM 不进入索引。查询按 NFKC、空格和大小写归一化，最多 128 码点、8 个词，AND 匹配、120ms 防抖，最多 200 个实体结果。

定位使用最新对象边界，支持列表滚动和约 1.5 秒宿主高亮；区域的列表定位切换本机空间展示。网格中的组/区域提示切换画布，不改共享 layoutMode。可返回一次定位前的相机、空间/列表展示方式和列表滚动位置。

“我的视角（此浏览器）”保存相机数值，不追踪内容目标。支持创建、按当前相机更新、改名、删除和跳转。每空间最多 50 条，归一化后名称唯一。Dexie 4 的独立 namedViews 表复用既有空间 key，按行 revision 在事务内比较更新；另一标签页修改会明确报冲突。相机偏好写入不覆盖命名视角，跨标签页视角列表更新也不驱动另一相机。

命名视角不上传、不进入文档历史、同步队列或文档导出；同一浏览器配置文件的其他使用者可能看见记录。未知未来版本和坏记录保留原样，坏的一条不隐藏其他有效视角。

## 当前版本和迁移命令

| 层次                                                 | 当前值               |
| ---------------------------------------------------- | -------------------- |
| documentVersion / schemaVersion / X-Nav-State-Schema | 3 / 3 / `3`          |
| canvasScene.version                                  | 1                    |
| canvasSettings.version / viewPreferences.version     | 1 / 1                |
| 网格 layoutVersion / 插件 manifestVersion            | 2 / 2，独立于产品 V2 |
| Dexie schema / NamedView.version                     | 4 / 1                |

当前写入入口精确要求文档 3；V1 写入返回 426，V2 连接旧协议服务端会暂停发送。未来数据不降级。普通 GET 不持久升级旧文档；所有服务端文档都迁移成功后才允许新写入。

先停写并做一致性 SQLite、uploads、配置及未同步草稿备份。在**隔离副本**完成迁移和恢复后再安排生产窗口。命令要求数据库路径已经存在，错误路径不会创建空库：

```bash
pnpm build
NAV_DB_PATH=/absolute/path/nav.db pnpm db:backup /absolute/path/nav-before-v2.db
NAV_DB_PATH=/absolute/path/nav.db pnpm canvas-v2-preflight
NAV_DB_PATH=/absolute/path/nav.db pnpm canvas-v2-dry-run
NAV_DB_PATH=/absolute/path/nav.db pnpm canvas-v2-migrate
```

预检与 dry-run 都回滚预演文档和备份写入。apply 每文档事务保存原行及 state_json，备份键 `canvas-scene-v2:<dashboardId>:<sourceRevision>`，再升级和 revision+1；重复执行不加版本。未能处理的文档回滚，其他已升级文档仍受全库停写保护。相机、几何、ID、配置和兼容 widget 行保留，组/区域不写成插件实例。

standalone 在 IndexedDB 事务中备份并升级文档，不重置空间 UUID 和当前相机。旧离线操作 ID 与 snapshot 原样隔离；新增编辑另存备份。恢复预览逐 ID 展示元数据、成员、区域和层序差异，并标明截断数量；完整双方快照可导出。恢复前再读最新远端，发生变化时要求重新核对；本地重提使用新操作 ID 和最新版本，仍受当前远端锁和 412 保护。

## 回滚

优先使用理解文档 3 的兼容修复版本。尚未产生 V2 编辑时，可停写并恢复匹配的应用、数据库和 uploads。已经产生 V2 编辑时，先保留当前库、全部草稿与本机数据；不能把版本号改回 2 或静默删除 scene。

确需降级到 V1 时，应在副本单独导出 scene 并人工核对语义损失，再决定几何/配置恢复方案。旧 V1 不能直接开启文档 3 写入；Dexie 4 也不能假定可由旧客户端降级打开。不要删除 IndexedDB 解决版本错误。

## 验证边界

本地使用 Linux x86_64、Node 24.19.0、可用 pnpm 11.25.0；项目和 CI 仍声明并使用 Node 22、pnpm 9.15.0，未修改 lockfile。2026-10-19 审查修复后的本地类型、ESLint、92 项测试、生产构建通过，改动文件格式另查。

已在隔离合成 SQLite 副本实际运行编译后的 preflight/dry-run/migrate；验证 dry-run 零写、版本 2→3、revision 7→8、重复执行、原行备份、分数/负坐标及原始尺寸/相机保留、兼容行镜像，以及数据库备份恢复。该演练不是生产部署副本验收。

首轮 GitHub 三浏览器开发回归为 59 通过、5 跳过、2 失败；V1 两项 WebKit 问题此次通过。新增失败来自测试初始化脚本在沙箱 iframe 访问 localStorage，已限制为只在顶层注入认证；保留 pageerror 与失败 trace 检查。第二轮发现可选 Boolean 属性的 Vue 默认值使选择工具隐藏，已显式设置默认值并保留浏览器回归。第三轮扩展批量撤销验收后定位到适配器并发初始化产生多个同页广播所有者的问题：它将本页保存误判为外部变更并清空历史。已改为共享初始化 Promise，并以原实现实际产生 3 个适配器、修复后只产生 1 个的反向回归确认。最终功能提交 `09e61fd67011c1d04e539208b49ab57980e007e3` 的 [CI run 39137566142](https://github.com/wymix-tech/Nav/actions/runs/39137566142) 全部适用步骤成功：80 项测试、三浏览器开发 64 通过/5 跳过、Chromium 生产 23 通过、Docker 构建成功。5 个跳过分别为开发环境不运行的 3 个生产离线壳场景，以及仅 Chromium 支持 CDP 注入的 2 个触屏场景。跳过不计为通过。

本地 Playwright 浏览器下载返回损坏包，Docker 不可用；三浏览器、生产壳和 Docker 已由上述 GitHub CI 补验通过。真实 macOS Safari、触控板、触屏、参考 PC 三轮性能对照与生产部署副本迁移/回滚仍未执行。100 个时钟在 V1 共享容器中的 p95 原本未稳定达到 33ms；V2 不宣称已达标。PR 保持草稿，不作为已通过全部 48 项发布门槛的声明。
