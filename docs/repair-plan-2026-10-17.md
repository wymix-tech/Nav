# Nav 完整修复方案

版本：1.0｜日期：2026-10-17｜状态：待实施。

仓库：[wymix-tech/Nav](https://github.com/wymix-tech/Nav)。本方案以评审基线 `cde7ff6f531d389b967b422ded4014d1f9335873` 为依据，覆盖《Nav 项目评审与优化方案》的全部 20 项问题。开始实施前需核对远端最新 main，将后续变动纳入差异检查；本文件不表示已经实施或验证修复。

## 1. 目标、范围与实施原则

目标是让 PC 笔记本、普通桌面、大屏、超宽屏、分屏窗口和竖屏均有可用、稳定的布局，同时保证配置不丢失、保存结果可见、公开访问边界明确。

本轮保留 Vue 3、Pinia、Dexie、Hono、SQLite 和现有内置组件。按九个可审查、可独立验证的 PR 推进，避免把安全热修复与布局数据迁移绑在同一次发布中。

必须遵守的约束：

1. 改变窗口、打开侧栏、浏览器缩放，不触发布局持久化。
2. 不用预设宽高比覆盖用户自定义高度；不在迁移中静默删除组件或配置。
3. 所有组件变更通过统一数据层；组件、Store 不再各自拼接写入 fetch。
4. 一个拖拽、缩放或清空动作形成一个原子变更；组件间碰撞结果一起保存。
5. 网络失败不能被视为保存成功，也不能自动把服务器模式切换为无认证编辑模式。
6. 安全修复先发布；旧数据兼容、可导出、可恢复后才启用新布局写入。
7. 文档和界面只声明实际支持的离线、同步及插件权限能力。

范围包括安全、认证、数据层、PC 布局、组件适配、编辑体验、第三方组件、系统监控、构建部署和回归测试。本轮不加入无限画布、多人实时协作、CRDT、全量视觉换肤或新业务组件。

## 2. 确定采用的技术方案

| 领域 | 本轮决策 | 作用 |
| --- | --- | --- |
| 布局来源 | 一套基准布局＋按需创建的断点覆盖布局 | 大小窗口往返时能恢复用户意图 |
| 屏幕判断 | ResizeObserver 测量实际内容容器，单位为 CSS px | 兼容分屏、侧栏和显示缩放 |
| 默认大屏策略 | 居中，内容最大宽度初始为 1600 px；提供铺满选项 | 避免组件被横向无限拉长 |
| 列数配置 | 自动列数或自定义列数上限 | 自定义值不能破坏窄窗口可用性 |
| 布局算法 | 独立纯函数；稳定排序；明确锚点；统一边界校验 | 便于验证越界、碰撞和确定性 |
| 交互保存 | 过程中内存预览，结束后一次批量提交 | 降低请求量并消除部分更新 |
| 数据写入 | 统一仓储层；本地事务；服务器模式使用本地快照与待同步队列 | 防止刷新丢失并支持断线恢复 |
| 同步冲突 | 版本比较＋保留双方快照＋明确选择 | 避免自动覆盖另一设备变更 |
| 插件 | 预构建模块运行于受限 iframe，停止直接在主页面 import 远程代码 | 建立真实的执行隔离边界 |
| 服务端校验 | 共享运行时 schema＋请求体与资源上限 | 拦截损坏状态与异常输入 |
| 发布 | 增量数据库迁移、功能开关、灰度与版本化备份 | 降低升级和回滚成本 |

1600 px 上限、组件最小尺寸和性能指标均为初始设计值，需在真实浏览器验收时校准；它们不是本次已测出的最佳值。

## 3. 首批修复：安全与认证

### 3.1 文件读取目录边界（S1，P0）

修改 `packages/server/src/index.ts`，将上传读取逻辑移入独立的上传服务与路由模块。

实施步骤：

1. 对路由解析后的文件名执行一次明确的格式校验，只接受已登记的服务端文件名；拒绝 `/`、`\\`、空字节、绝对路径、点目录和异常百分号编码。避免多处重复解码。
2. 使用上传记录中的物理文件名定位资源，不允许请求参数直接决定任意磁盘路径。
3. 对规范路径执行目录包含关系检查；使用 relative/分隔符边界，不能仅做字符串前缀判断。
4. 读取前处理真实路径和符号链接边界；上传目录仅由应用写入，禁止外部用户创建链接。有条件时使用防链接跟随的文件打开方式。
5. 以安全流方式返回文件，关闭句柄；正常不存在资源返回 404，异常路径统一拒绝，不泄露绝对路径。
6. 新上传的资源保存检测后的 MIME、尺寸、大小、摘要、生成文件名。原文件名仅作显示，不参与路径生成。

兼容旧文件：生成文件名和元数据清单，逐项检查真实内容与路径；符合原合法文件名规则的安全栅格图片保留旧 URL。未登记资源进入待检查状态，不能为兼容旧 URL 重新开放任意路径访问。

验收：使用临时目录验证普通图片可读，目录外哨兵、编码分隔符、双重编码、绝对路径、符号链接均不可读。测试禁止使用真实密钥或系统敏感文件。

### 3.2 上传类型、SVG 与请求上限（S2）

- 新上传仅接受 JPEG、PNG、WebP、GIF；本轮关闭 SVG 上传和已有 SVG 的公开内联返回。
- 文件扩展名与 MIME 均由内容检测/解码结果确定；不信任客户端 MIME。
- 在 multipart 解析前限制整个请求体，初始 6 MiB；文件本体上限仍为 5 MiB。流式传输及伪造 Content-Length 同样必须受限。
- 解码前检查像素和帧数预算；初始静态图上限 20 MP，动画按累计帧像素和解码时间限制，防止小文件高解码成本。具体阈值写入服务端配置。
- 静态栅格图片解码后重新编码并去除不需要的元数据。GIF 仅在所选编解码库支持安全保留动画及预算限制时继续提供动画，否则明确提示并转换为静态图片，不能静默改变能力。
- 使用受维护的图像解码库；实施时核对其官方文档、Node/Alpine 支持、原生依赖及锁定版本，不以本方案日期推断“最新版本”。
- 返回正确 Content-Type、`X-Content-Type-Options: nosniff`；旧 SVG 进入隔离/下载流程，由管理员替换或转换后更新引用。
- 补充上传总配额、删除背景引用后的延迟清理。清理只作用于无引用且超过保留期的文件，首轮运行仅报告，不自动删除旧资源。

验收：SVG、HTML、伪造 MIME、扩展名冲突、损坏图片、超限请求与解码预算超限均返回明确错误；合法图片升级前后仍可显示。

### 3.3 登录验证、授权状态与限流（A1、S3、U2）

保留服务端现有 `POST /api/auth/verify`，前端显式使用 POST。只有 JSON 响应且 `valid === true` 才完成验证；禁止将 HTML 200 当成登录有效。

认证 Store 区分 checking、authenticated、anonymous、unavailable。启动验证期间不可编辑；网络不可用不等同于 token 已无效，也不等同于已通过认证。登出立即结束编辑、取消指针交互、关闭需要权限的面板并暂停远端队列。

API 统一处理 401、403、429；401 暂停队列并显示登录入口，403 显示权限原因，429 尊重 Retry-After。失败队列不得自动用其他登录会话继续发送，恢复时检查实例和权限作用域。

限流只从受信任代理链提取客户地址，默认使用实际连接对端地址。代理列表由配置提供，按链条从受信任一侧解析；不直接使用客户端提交的完整 x-forwarded-for 字符串。单进程版本采用有 TTL、容量上限和清理机制的存储，并增加全局并发保护；如未来部署多实例，再接共享限流存储。

改用异步 bcrypt；限制密码输入长度，避免无效类型触发 500。对 JWT 显式限制允许算法与角色，并统一有效期响应。若引入 issuer/audience，需要版本化迁移；旧 token 可要求重新登录，不改变现有密码验证结果。

保留当前 Bearer 协议，优先移除同源活动上传内容和主页面远程插件执行路径。不能声称 CSP 或前端状态判断已经解决全部 XSS。JWT 在没有服务端会话记录时不具备单 token 即时撤销能力；文档明确通过密钥轮换使旧 token 失效，不承诺尚未实现的撤销接口。

未知 `/api/*` 必须返回 JSON 404；API、uploads 与静态资源不能落入 SPA 页面回退。

## 4. 数据层统一与离线同步

### 4.1 运行模式与权限边界

明确区分 standalone 和 server 模式。服务器部署构建默认 server，纯静态离线发行版显式选择 standalone；运行模式来自部署配置，不由一次 health 超时决定。

standalone 模式只写 IndexedDB，不发送组件写入 API。server 模式缓存可读快照，但后端不可达时不能自动开放匿名编辑。已验证且尚未过期的编辑会话可以保存离线草稿；服务器最终仍重新校验权限。会话过期后保留草稿并提示重新登录。

缓存键至少包含站点 origin、服务实例标识、dashboardId、权限作用域。旧的本地独立仪表盘与服务器快照分开；不能在登录时自动把两者覆盖合并。需要导入时，先显示差异并保留副本。

### 4.2 统一仓储契约（D1、D2）

新增仓储层承接 `loadSnapshot()`、`commitMutation()`、`getSaveState()`、`retry()`、`exportDraft()`；底层分别使用 LocalAdapter 与远端传输。具体 TypeScript 命名可随项目风格调整，但职责不得再分散回 Store。

一次 mutation 包含稳定 operationId、dashboardId、基准 revision、本地序列号及变更内容。组件由客户端生成最终 UUID，服务端接受且校验；不再先用临时 ID 后替换。

本地一次事务同时写入新快照与待同步项，成功后 UI 才能显示“已保存到本机”。事务失败时恢复到上个状态或保留明确的未保存草稿，不能显示已保存。Store 暴露以下状态：

| 状态 | 用户提示 | 后续动作 |
| --- | --- | --- |
| saving-local | 正在保存 | 等待事务结果 |
| local-only | 已保存到本机 | standalone 正常完成 |
| pending-sync | 已保存到本机，等待同步 | 有网且授权有效时发送 |
| syncing | 正在同步 | 等待服务端确认 |
| synced | 已同步 | 记录实际确认版本和时间 |
| conflict | 检测到另一处修改 | 保留双方快照，用户处理 |
| auth-required | 需要登录才能同步 | 保留队列，不重试写入 |
| error | 保存或同步失败 | 原因、重试与导出入口 |

新增、删除、配置、布局、偏好设置、插件安装及卸载均走统一接口；UI 层不直接 fetch 写接口。API client 必须检查所有非 2xx、Content-Type 和响应 schema；禁止空 catch 吞掉写入失败。

### 4.3 服务端原子写入与版本协议

为仪表盘聚合状态增加 revision，新增 `PUT /api/dashboards/:id/state`；请求携带 If-Match 和 operationId，一次事务更新仪表盘、组件集合及 revision。

- 不携带必要版本条件返回 428；版本不匹配返回 412，附当前 revision 和安全的冲突信息。
- operationId 去重记录与业务状态在同一事务提交。相同 ID、相同请求摘要重试时返回原成功结果；相同 ID 不同内容返回 409。
- 去重检查在鉴权之后、版本比较之前，保证“已成功但响应丢失”的重试可取回原确认结果。
- 旧 widgets 增删改接口在兼容期内仍调用同一事务层并递增 revision；不允许旧接口绕过新版本体系。对于无法安全携带版本的旧客户端，切换新协议后返回升级提示，不能继续盲写覆盖。
- 删除组件、清空、碰撞导致的多组件布局变化均原子执行。
- 安装组件属于实例级目录，拥有独立 revision 和幂等操作；卸载默认仅当无仪表盘引用时允许，有引用则返回冲突。需要级联卸载必须显式提交原子操作。

数据库迁移新增版本和操作记录，保留原表及可读字段，不在首轮删列。共享类型增加 schemaVersion，服务端统一校验快照。

### 4.4 队列、断线恢复与多设备冲突

每个仪表盘串行发送变更；pointermove 不入队，交互结束才生成操作。尚未发送的连续配置/布局可以合并；已经发出的 operationId 和请求内容必须保持不变。

网络错误、408、部分 5xx 使用带抖动的指数退避，前台显示暂停或恢复；401/403、schema 错误与 412 不盲目重试。若服务端已提交但响应丢失，重用原 operationId。队列超过保留上限前提示导出，不能静默丢弃。

发送期间又有本地修改时，确认只推进已发送的本地序列与远端 revision，不能用旧响应覆盖更新的 UI。后续本地操作只有在确认属于同一条本地变更链时才能衔接新版本。

发现远端版本变化时，保留 localDraft、remoteSnapshot、baseSnapshot。首版不实现自动字段级合并：提供“采用远端”“基于当前远端重新应用本地草稿”“导出双方副本”。选择本地后仍需带最新 If-Match 提交；如再次冲突则重新处理，不能强制覆盖。

页面重新可见时检查版本；前台可按初始 30 秒间隔有条件拉取，离线、编辑提交中与隐藏页面暂停。多标签页通过 BroadcastChannel 或等效机制通知版本变化；发送前重新读取队列并通过原子认领避免两个标签页各自发送新操作，operationId 作为最终防线。

### 4.5 离线资源边界

Service Worker 作为独立子任务交付：只缓存带版本的应用壳和静态资源，不缓存登录响应或写请求；公开仪表盘快照继续由仓储层管理。插件与天气的离线可用性单独展示，不能因应用壳已缓存就承诺全部外部内容可用。

新版本发现时提示刷新，不在拖拽或未保存草稿中强制激活。首次从未加载过的页面无法凭空离线启动；文档明确“成功加载并缓存后支持离线打开”。

## 5. PC 布局与响应式核心设计

### 5.1 数据模型

新增 `layoutVersion: 2`，保留以下逻辑字段：

| 字段 | 含义 |
| --- | --- |
| baseLayout | 用户基准布局，含每个组件的 x/y/w/h 和 baseColumns |
| profiles | 用户明确编辑过的布局快照，按断点与有效列数索引 |
| columnMode | auto 或 custom；custom 表示列数上限 |
| preferredColumns | 自定义列数上限，初始范围 4–24、步长 2 |
| contentWidthMode | centered 或 fluid |
| maxContentWidth | centered 初始值 1600 CSS px，可在设置中调整 |
| rowHeight / gap | 保留旧 rowHeight，默认 80 / 10 CSS px |
| layoutRevision | 随明确的布局编辑推进，用于生成缓存失效与冲突判断 |

profiles 的键包含稳定 breakpoint 和 effectiveColumns，不包含窗口的每个像素宽度。只在该配置下明确编辑时创建覆盖布局；自动派生不能写入数据库。

渲染优先级固定为：匹配当前列数的用户 profile → 匹配列数的 baseLayout → 从 baseLayout 派生。修改一个 profile 不改写其他 profile；用户可执行“将当前布局设为基准”或“重置当前断点”，这两项才是显式持久化动作。

旧 md/sm/xs 常为占位数据。迁移时不能直接启用它们，否则组件可能全部重叠。只有经过完整性、非占位和边界检查的旧断点数据才作为候选；其他内容原样保存在备份中。

### 5.2 容器宽度、列数和大屏行为（L1、L5、L6）

用 ResizeObserver 测量实际网格内容宽度 W，外边距、侧栏占用在测量前扣除。只因高度变化或竖屏方向变化，不切成单列。

初始自动策略如下；W 是实际内容宽度，不是物理分辨率：

| W | 展示方式 | 自动列数 |
| --- | --- | ---: |
| <768 px | 单列展示，可排序 | 1 个展示列，不改写基准网格单位 |
| 768–1199 px | 紧凑网格 | 8 |
| 1200–1919 px | 标准网格 | 12 |
| 1920–2559 px | 宽网格，通常来自 fluid 模式 | 16 |
| ≥2560 px | 超宽网格，通常来自 fluid 模式 | 24 |

centered 模式最大宽度 1600，因此通常停留在 12 列，控制卡片横向拉伸。fluid 模式允许宽屏放入更多组件；宽布局初次派生时保留组件跨度和高度，不把每张卡片同比例放大。

custom 模式将 preferredColumns 当作上限，结合最小轨道宽度算出实际可容纳列数；窄窗口无法容纳时自动减少，并在设置中显示“上限 12，当前 8”。不保留会造成内容不可用的强制列数模式。

布局断点与组件展示断点分开：布局决定卡片位置，组件根据自身容器宽高决定内容密度。CSS 使用 `repeat(C, minmax(0, 1fr))`，不允许越界布局制造隐式列。

### 5.3 派生、边界与碰撞算法（L2、L3、L4）

新增纯函数模块：normalizeLayout、deriveLayout、resolveCollisions、findPlacement、validateLayout。算法不读取 DOM、不访问 Store、不执行网络请求。

每个合法网格布局必须满足：x/y/w/h 为有限整数；x,y≥0；w,h≥1；x+w≤C；高度不低于组件约束；组件无重叠。对历史异常输入，生成可见的修复结果和报告，不无声丢数据。

派生规则：

1. 基准列数相同且布局有效时原样展示，保留用户空隙和自定义高度。
2. 不同列数且没有 profile 时，以基准 `(y,x,id)` 稳定排序，保留 h；w 保留原跨度，在组件最小宽度和当前列数间约束。
3. 使用确定性的 first-fit 放置。派生布局可以重新排布，但不写回 base；每次都从 base 计算，禁止连续从上一个缩小后的布局再缩放，防止累计漂移。
4. 相同输入必须得到相同输出。增加组件时找真实可用位置，没有原先扫描 50 行后回落到 (0,0) 的路径；达到布局上限时返回明确错误。
5. 用户调整列数也只切换展示。保存此断点时生成 profile，重置时可回到原 base；不调用旧 adaptAllWidgets 覆盖高度。

碰撞规则：当前拖动/缩放组件为锚点，先夹紧其边界并优先放置；其他组件按原位置稳定排序，只在碰撞时向下寻找可用位置。求解整套布局后统一应用，禁止跳过 changedId 的实际结果。全局“自动整理”是独立显式操作，不在每次拖动时意外消除所有用户空白。

最小像素宽度折算为最小跨度；若当前容器无法达到最小宽度，则进入组件紧凑展示或单列降级。不能为了满足 minW 再次把 w 放大到 C 以外。

### 5.4 拖拽、缩放与定位统一（L2、U2）

统一几何关系：列宽 `cw=(W-(C-1)*gap)/C`；组件左侧 `x*(cw+gap)`；宽度 `w*cw+(w-1)*gap`；行方向同理。预览、高亮、指针换算与真实 CSS 使用同一模块，消除原 (C+1) gap 计算差异。

采用 Pointer Events 与 pointer capture；从滚动容器坐标计算位置，处理 pointerup、pointercancel、lostpointercapture、Escape、组件卸载和权限变化。浮动预览放入独立顶层覆盖层，避免祖先 transform/overflow 改变 fixed 定位或裁切。

pointermove 经 requestAnimationFrame 合并，只修改交互草稿。pointerup 校验最终布局后提交一个原子 mutation；取消则恢复交互前快照，不发送网络请求。正在拖动时暂缓应用容器断点变化，结束后根据最新宽度重新派生；不把旧宽度算出的坐标直接写入新列数布局。

支持边缘自动滚动；普通内容点击与拖动通过移动阈值区分。单列模式提供上移/下移或拖动排序，顺序只存入当前 profile。提供位置与尺寸的键盘调整入口，完成同样走统一校验与保存路径。

### 5.5 撤销与重做

一次完成的拖拽、缩放、自动整理、清空或偏好提交对应一个历史记录，初始保留最近 50 条。撤销会产生新的、带当前 revision 的 mutation，不把服务端版本倒退。

新操作清空重做栈；远端冲突或采用远端快照后重新建立历史边界，防止旧撤销操作覆盖其他设备修改。窗口变化不进入历史记录。

## 6. 内置组件、偏好与编辑体验

### 6.1 尺寸契约与容器展示（L5）

以下为紧凑模式最小内容宽高的初始值，最终以长文本、不同字体和缩放验收为准：

| 组件 | 初始最小宽×高 | 紧凑展示策略 |
| --- | --- | --- |
| 搜索 | 280×80 px | 收起次要选项，保留输入、引擎和搜索按钮 |
| 时钟 | 200×110 px | 有上限的流式字号，优先保证完整时间可读 |
| 天气 | 240×150 px | 减少装饰图和次要指标，保留城市、温度、状态 |
| 书签 | 200×140 px | 自动列数、长标题省略但可查看完整标题、内部滚动 |
| 监控 | 260×180 px | 显示选定核心指标，详情内部滚动或展开 |

组件契约集中维护，添加默认值、拖拽最小尺寸、缩放与 manifest 使用同一来源。网格单位与像素约束分别命名，不能混用。

去除不必要的多层裁切；长内容使用组件内部明确滚动区。所有弹窗在视口级呈现，并具有最大高度与滚动，不随卡片尺寸被裁切。布局行高保持可解释，不把窗口高度直接映射为所有卡片的任意缩放。

### 6.2 偏好设置事务（U1）

打开面板时深拷贝标题、布局设置和背景数据为 draft。预览使用独立临时状态，取消统一恢复 document.title、主题和背景预览。

保存先校验草稿，再提交一次 mutation；本地事务失败保持面板与草稿，并提示重试。server 模式远端不可达时显示“已保存到本机，待同步”，不能显示无条件的远端成功。

上传资源与引用状态分开：上传完成不等于偏好已保存。取消后未引用的新资源按保留期清理，不立即删除共享资源。上传失败和格式错误必须在面板可见。

### 6.3 编辑入口与组件库（U2）

激活点改为真实 button，支持 click、Enter、Space、focus-within；悬停只作辅助。编辑权限统一由认证状态与运行模式推导，删除、清空、设置、拖拽、缩放使用同一守卫。

大屏组件库以可收起侧栏呈现并给内容区让位；窄屏使用有关闭入口的抽屉。网格开始指针交互时通过显式事件协调组件库，不再依赖不会触发的 HTML dragstart。

统一模态框：Teleport 到视口级容器，语义、初始焦点、焦点约束、Escape、关闭后焦点恢复、滚动锁定、窄高窗口可滚动。保留 visible focus，并支持减少动画偏好。

### 6.4 天气、书签与外部请求（F1、V1）

天气统一进入请求服务，默认缓存 10 分钟；前台按过期时间刷新，重新可见时补查。请求设定超时和 AbortController，切换城市取消前次请求或使用序号隔离；禁止旧结果覆盖新城市。

请求失败保留最近成功数据，展示更新时间及过期状态；重试有退避。单位换算尽可能复用已获取数据，不能因仅切换摄氏/华氏就触发无意义请求。

书签仅接受支持的 http/https URL；输入缺少协议时可提示补全，拒绝 javascript/data 等活动地址。外链显式使用 noopener，图标失败显示本地占位，并提供图标外部请求的关闭选项。字体使用系统回退或随应用提供，不能因第三方字体不可达影响主要操作。

## 7. 第三方组件协议修复（E1）

先关闭任意远程模块在主页面直接 import 的路径，已有插件标记为“需要升级”，保留配置与位置，不删除用户数据。仅修正 cdnUrl 后继续主上下文执行，不算完成此项修复。

定义 manifestVersion=2，入口必须是可在浏览器执行的预构建 ESM bundle，不接受原始 `.vue`。模块自带运行时依赖，提供明确 mount/unmount、config 更新接口。采用受控 iframe runner 加载，主页面不向插件传递 token、仓储对象或原始 DOM 能力。

安装链路统一为：严格解析 github.com 仓库 URL → 解析不可变提交 → 从同一提交读取 manifest → 校验入口路径与 schema → 显示权限和来源 → 持久化 entryUrl、提交标识及授予权限 → 隔离加载。

使用 URL 解析器校验协议、主机、路径，不允许相似域名或非预期凭据。入口必须位于所选仓库提交产物下，拒绝越界路径和任意外部重定向。服务端如需代理拉取，必须限制目标域名、重定向、响应大小和超时，不能引入任意 URL 抓取接口。

runner 使用 sandbox 允许脚本但不授予同源、顶层导航和任意弹窗能力；由应用生成 CSP，仅允许选定的版本化入口资源及用户明确批准的网络/图片来源。仅设置 sandbox 不能声称已限制全部外部网络。CSP、编码转义和动态模块依赖需用实际浏览器验证。

iframe 为不透明来源时，不依赖消息的 origin 值完成认证；校验 event.source、初始化随机凭据及消息 schema，优先建立专用 MessageChannel。配置只传递该插件所需字段，限制消息大小、频率与 resize 范围，销毁时关闭通道。

服务端和本地数据库都保存相同的安装记录，刷新不丢 entryUrl。缺少依赖、加载超时、CORS 或 CSP 拒绝时显示占位、原因和重试；失败插件不能拖垮仪表盘。

卸载先处理组件引用，完整流程保持原子性。README 提供与实际协议一致的最小示例、构建命令和兼容说明；permissions 只有被 runner/CSP/消息 API 实际执行时才标为已限制。

## 8. 系统监控与服务端质量（评审 P1、V1）

评审中编号 P1 是监控问题的条目 ID，不是此处的优先级简称。

### 8.1 监控采样和公开策略

系统监控默认仅管理员可读；公开仪表盘在未启用公开监控时显示合适的占位，不暴露主机信息。确需访客可见时，管理员显式启用，并仅返回选定指标，默认隐藏 hostname、完整路径及不必要型号。

新增独立采样服务：CPU 使用两次 tick 差值；内存、磁盘和 GPU 后台异步采集并缓存。外部命令异步运行、固定参数、并发上限、超时与失败熔断；API 只读取缓存，不在请求线程执行 execSync。

磁盘路径使用管理员配置的允许列表，公开 API 只接受路径标识，不接受任意文件系统路径；限制项目数。容器环境明确统计的是容器还是宿主机，不能把 os.totalmem 等结果直接称为容器配额使用率；是否支持 cgroup 指标按实际实现注明。

前端同源监控组件共享采样订阅，隐藏页面暂停，保留最近成功数据。初始采样/展示周期为 5 秒；前端 refresh 配置设上下限，避免负值或 0 产生快速轮询。

### 8.2 输入、响应与资源上限

在 shared 内定义运行时 schema，并在服务端实际执行，TypeScript 接口不能替代运行时校验。

初始默认限制：布局列数 1–24；行高 40–200；坐标与高度为有界整数；单组件 config 不超过 16 KiB；仪表盘状态请求不超过 2 MiB；组件数量默认上限 100，可由服务端配置。偏好和插件配置也使用对应 schema。

旧数据超过新上限时先报告并导出，不静默截断；升级预检需确认阈值能容纳已有合法数据，必要时提高配置后迁移。非法旧数据进入可恢复草稿，避免迁移成功却再也无法保存。

统一返回 400/422 校验错误、401/403 认证授权错误、404 不存在、409 语义冲突、412 版本冲突、413 超限、429 限流、500 内部错误。日志带 requestId/operationId，不能记录密码、token 和完整敏感配置。

## 9. 数据迁移、兼容与回滚

### 9.1 升级前预检

记录实际部署提交、数据库 schema、配置、上传目录和 IndexedDB 版本。通过 SQLite backup API 或一致性停机方式备份；WAL 模式不能仅复制正在写入的主 db 文件而忽略未合并日志。

生成只读迁移报告：组件数、缺失引用、重复 ID、非法布局、旧断点占位、超限配置、SVG/未知上传类型、安装组件记录。提供下载备份入口，不能要求用户手工抄出数据。

### 9.2 布局与缓存迁移

迁移采用事务与显式版本，满足幂等；重复启动不重复备份、不重复生成组件。

1. 将旧仪表盘和全部组件原始 JSON 保存为不可变备份，标记源版本与校验摘要。
2. 将旧 columns、rowHeight、lg 原样转为 base；旧 columns 为用户可能设置的偏好，不擅自重置为 12。
3. 运行归一化产生新布局候选，并记录哪些组件有调整。只修复不合法坐标与碰撞，不用最佳比例重算合法高度。
4. 默认启用自动适配；centered 初始 1600 px。已有特定列数偏好保留为 custom 上限，同时明确当前有效列数。若列数来源无法区分，界面提供切换自动入口，迁移说明列出所采用规则。
5. 保留全部旧 md/sm/xs 备份；已确认不是占位的有效布局才可转为 profile。
6. 写入 layoutVersion=2，并标记迁移完成。迁移失败回滚事务，保留原数据和只读导出入口。

IndexedDB 版本升级新增快照、outbox 与迁移备份，不先删除旧表。避免旧标签页与新标签页并行写入：处理 versionchange、提示刷新，并在新协议启用后停止旧协议写入。

### 9.3 回滚路径

安全热修复提交必须保留，任何功能回滚都不能退回目录穿越或活动上传未隔离的版本。

数据库先采用加表/加列的扩展迁移；回滚到“已修安全、能理解新 schema 的兼容版本”，不能承诺原始 cde7ff6 可直接读取所有新结构。

尚未开启 v2 写入时，可关闭布局功能开关回到兼容渲染。开启后如需回退，要么用兼容版本从最新状态导出旧格式，要么进入维护窗口恢复备份并明确备份之后的变更损失；有待同步队列时先导出并暂停发送。禁止一边恢复旧数据库一边让新客户端继续重放操作。

每个发布记录代码回滚点、数据库备份、资源清单和实际兼容边界。资源清理延后到回滚窗口之后。

2. 两组件重叠、交叉拖动与连续缩放后无重叠；保留合法的用户高度。
3. 12→8→12 列、大窗口→半屏→恢复，只派生显示，不产生写入请求，基准摘要不变。
4. 在某个断点编辑后只影响该 profile；“设为基准”和“重置断点”可撤销。
5. 本地新增、配置、拖拽、缩放、删除后刷新，状态一致；本地事务失败不会虚报保存。
6. 新增后立即配置/删除，最终 UUID 不变，远端不留下幽灵组件。
7. 服务端提交成功但响应丢失，重试不重复新增；请求乱序不覆盖最终布局。
8. 断线编辑后刷新草稿保留，恢复网络自动进入有序同步；会话过期则暂停并保留队列。
9. 两设备同时编辑返回明确冲突，双方状态可导出，不默认覆盖另一方。
10. 图片增删、标题及主题预览后取消，持久化和当前显示恢复；上传失败可见。
11. 登出或 token 失效立即停止编辑；API HTML、错误 JSON 和超时均不能视为认证成功。
12. 第三方插件安装后刷新仍可用，超时有占位；不能读取主页面 localStorage、替换主页面或发送未授权消息。
13. 上传目录外、SVG、伪造 MIME、超限流式请求均被正确拦截；合法旧图片升级后保持可读。
14. 模拟 GPU 采集超时，health、登录与保存请求仍能处理；CPU 指标来自采样差值。
15. 干净 checkout 无缓存可构建；旧版本数据迁移幂等，失败可恢复，安全补丁回滚时仍保留。

### 12.4 性能目标

先在固定浏览器、机器规格和 30 个组件基准数据上记录现状。初始目标为拖拽指针到可见更新 p95≤50 ms，布局解算不产生超过 100 ms 的长任务；50 组件作为扩展压力场景。该数值是待验证目标，不是已达成结果。

pointermove 期间持久化写入与网络请求数为 0；一次完成的交互通常生成一个聚合操作。30 个监控卡片共享一次周期拉取；同一后端采样周期不因访客数量倍增而重复执行外部命令。

服务端安全限额、队列容量与缓存保留策略必须具备配置与超限行为；不为追求 FPS 禁用验证或丢弃待同步状态。

## 13. 构建、部署与完成定义

固定并验证项目声明的包管理器和 Node 运行时，所有依赖变更同步锁文件；不把评审环境 pnpm 11 的构建策略误判成项目 pnpm 9 必须修改的行为。检查部署运行时是否仍获维护，若需升级，单独验证原生 SQLite/图像依赖和 Docker 镜像。

移除已跟踪的 tsbuildinfo，保证 dist 缺失时 shared 构建生成声明。统一根命令：安装锁定依赖 → shared 构建 → 类型与静态检查 → 单元/路由/仓储测试 → 前后端构建 → 浏览器与 Docker 冒烟。根 lint 应明确包含什么，不能把纯类型检查称为完整代码规范检查。

Docker 不再在无等价前置保证时跳过前端类型检查；生产镜像使用非 root 账户并赋予数据目录所需权限。备份、迁移和健康检查必须在真实容器目录挂载下验证。

prod.sh 移除个人 PATH 假设；build/status/stop 不要求登录密码，start 接受 NAV_PASSWORD_HASH 或 NAV_PASSWORD。提供幂等迁移入口、备份说明、代理配置和失败排查；静态资源、上传和 API 的路由各自明确。

最终完成需要同时满足：全部 20 项评审问题有对应改动与证据；安全与数据关键用例通过；真实浏览器 PC 核心矩阵通过；迁移和回滚演练通过；对未完成的外部能力或兼容限制有准确说明。不能以“类型检查通过”或“构建成功”替代功能验收。
