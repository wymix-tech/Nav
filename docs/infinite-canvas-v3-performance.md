## 性能边界

密集时钟场景 safe 的完整采样窗口记录 101 个长任务，observe 为 9 个，三轮 p95 如上表。减少详情数不能直接等同于交互达标。这些数据尚不能区分挂载、调度、时钟更新与软件绘制各自的贡献，完整归因需要独立主线程/GPU profile。
共享环境中仍有超过 33ms 的 p95。参考 PC 和真实 Safari 的性能验收仍保持开放；共享环境结果不能替代它们。full/observe 可用于保留全部详情的回退对照。

## 复现冻结 V2 对照

从 V3 仓库根目录复制同一测试工具到独立 V2 worktree；只复制测试文件，不改 V2 packages。先完成依赖安装和生产构建，再顺序测量，不能与其他测试或构建并行。使用同一已安装的 Chromium 和相同环境。

```bash
git worktree add --detach ../Nav-v2-perf 899b4561b6faec0f4d8b0c5a2871a800ae1b29d2
mkdir -p ../Nav-v2-perf/tests/helpers
cp tests/performance.spec.ts ../Nav-v2-perf/tests/
cp tests/helpers/browserTest.ts tests/helpers/runtimeFixture.ts ../Nav-v2-perf/tests/helpers/
cp playwright.performance.config.ts ../Nav-v2-perf/
cd ../Nav-v2-perf
pnpm install --frozen-lockfile
pnpm build
NAV_TEST_DIST=true NAV_PERF_MODE=v2 pnpm exec playwright test -c playwright.performance.config.ts
```

回到 V3 仓库，在生产构建完成后执行：

```bash
for perf_mode in observe safe full; do
  NAV_TEST_DIST=true NAV_PERF_MODE="$perf_mode" pnpm test:performance
done
pnpm benchmark:spatial
```

## 决策和未完成项

- 保持 100 组件、schema/document 3、Dexie 4 和 manifest 2；没有扩大生产预算或新增数据库迁移。
- 合法 100 组件的大配置样本已经产生显著的完整快照与 50 份历史字节成本；按同配置密度扩大只会继续增加这些成本。几何查询微基准不能证明整盘校验、队列、历史、服务端保存及恢复预览具备相同扩展能力。
- 按需 View 和共享服务的资源变化应结合详情数、请求计数与生命周期回归判断；不承诺整盘旧插件可以暂停执行，也不以强制卸载输入/聊天/iframe 达成数字。
- 增量命令和空间分块继续作为独立扩展，具体协议与启用条件见方案第 16 节。需要测量真实本地写入和发送链路，再决定是否引入 command transport；需要完整 revision/read-token、离线与恢复矩阵后再讨论分块。
- 当前尚无参考 PC p95≤33ms、定位 ready p95≤300ms 的完整正式档案；真实 IndexedDB 写入/发送、逐帧主线程拆分、强保护集合、真实 Safari/触屏/缩放、生产副本升级/回滚仍待验收。
- 验证清单中的 partial/manual-pending 保留；共享容器数据不能消除这些发布门槛。
